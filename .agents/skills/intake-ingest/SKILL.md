## Source modes

In contained mode, confirmed workspace authority permits reading and retaining
the exact stable group. Do not add a second classification gate. Recheck the
group before first read and before commit. Preserve originals byte-for-byte
under sources/contained/.

In separated mode, display the exact group once and obtain one group
confirmation before content access. Apply GREEN/YELLOW/RED and metadata-only
manifest-disposition rules; create no new `sources/pointers/` file.
Ask again only when the group changes or its bounds remain unresolved.

1. Reject links/reparse points and unsafe path classes.

   in this candidate. Duplicate or unstable input keys stop; an uncommitted

## Protected staged-tree procedure

With assistant-save authority, the visible coordinator is the sole stager and
committer. Under 5C, the owner is the sole stager and committer; the visible
coordinator only verifies, records, reviews, and issues the exact section-23
handoffs read-only around those owner actions.

1. Complete the Standard/Deep governing trace and load all of TRACER.md. A
   truncated tool rendering or omitted range is incomplete; measure the file
   and read bounded contiguous slices through EOF before drafting.
2. Require governance, adapters, rubric, tools, and configuration committed and
   outside this claim checkpoint; reload them after any maintenance change.
3. Draft the entire delta, including exact register/state pair when generation
   or register bytes change. A protected surface change with no new register row
   still increments generation once.
4. Validate IDs, versions, projections, typed references, transitions,
   evidence, dependency closure, raw register SHA-256, and generation.
5. Reread every semantic draft, then capture one `sealed_at` in strict UTC
   milliseconds and make every appended row's `recorded_at` identical to it.
   Any later candidate-byte change requires a new time and seal.
6. Require one exact dirty set containing every protected path in the
   generation. With assistant-save authority require an empty index. Under 5C,
   require section 23's prior owner-staging handoff and read-only verification
   of the complete participant-reported index before review; do not restage it.
7. Run Reference section 15's Git-environment/root preflight. With assistant-
   save authority, stage only sorted declared paths. Under 5C, make no Git
   mutation and read-only reverify the already recorded owner-staged tree.
8. Record schema, kind, base_head_oid, staged_tree_oid from git write-tree,
    sealed_at,
    declared_paths, exact add/modify/type-change/delete entries, reviewer identity,
   governing trace reference/SHA-256/mode, rubric SHA-256, object format,
   review-materials SHA-256, and review iteration. Create the deterministic
   pre-review snapshot required by Reference section 29.
9. Dispatch a genuinely separate reviewer against the frozen candidate and
   tracked rubric.
10. After return, recheck HEAD, staged-tree OID, staged paths, candidate bytes,
   status, and mutation evidence. Any mismatch invalidates review.
11. Capture the exact returned UTF-8 JSON bytes without parsing/reserializing;
    store their SHA-256 and base64 in the final wrapper with exact pre/post
    snapshot bytes and mutation evidence. Save a local sidecar qualified by
    tree, iteration, and response hash. Every independence note states the
    actual harness mechanism and correlation limits.
12. Put the exact final-wrapper base64 and SHA-256 plus base and tree OIDs in
    the prepared commit body. Save only an accepted unchanged candidate. With
    assistant-save authority, commit and verify its sole parent, tree, and
    changed-path set against the reviewed bindings. Under 5C, bind the message
    in the receipt, issue section 23's owner-commit handoff, and stop; after the
    participant reports saving, accept it only through the read-only owner-
    commit recovery oracle.
13. On reject/inconclusive, append the exact wrapper binding to the receipt and
    enter `blocked`. Only after a direct owner decision is recorded and the
    next verified `reviewer-repair` recovery event is appended may assistant-
    save authority unstage declared paths; preserve working files. Under 5C,
    after that same event, ask the owner to unstage those exact
    paths and use only read-only verification afterward. One direct owner
    decision may consume one Deep result for repair and fresh review; record it
    durably in `review_attempts`. A second nonaccept blocks further revision in
    that checkpoint and requires owner-directed cancellation/rollback or
    maintainer recovery; it never permits a review bypass.

Review evidence is process evidence, not factual claim evidence. It does not
replace owner authority or truthful evidence.

## Recovery

Only an authentic consistent existing dossier and strict section-23 receipt,
plus applicable direct or saved authority, permits mutating recovery. Otherwise
report the evidence and stop unchanged for maintainer recovery. When permitted,
preserve the incomplete tree first by appending the next immutable section-23
recovery event. Its create-once manifest and deterministic flat snapshot leaves
live under `caches/recovery/<checkpoint-id>/`; every event is ordered and
retained in the checkpoint receipt. The newest event may resume only its same
interrupted transition under section 23's exact mixed-state oracle; a distinct
later transition requires a new event. Resume only
when:

- recorded base HEAD still matches, or the exact completed commit exists;
- affected paths match the dossier's recovery record;
- each path matches a recorded prior, partial, or intended state;
- staged entries, if any, match the recorded tree and paths;
- source inputs match recorded fingerprints; and
- any pending legacy-authority rebind matches its receipt-bound prior or
  intended hash and complete recovery event; and
- unrelated work will not be included or overwritten.

If the exact commit succeeded, finish only verification, a receipt-bound
profile-renewal authority rebind, and section-28-authorized byte-verified
duplicate deletion and reviewed-but-unstored holding moves; never roll it back.

`drafting` to `staged` only after read-only recovery proves its complete index
